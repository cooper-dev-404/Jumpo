## 窗口实机检查步骤

1. 先构建最终 Jumpo 包，再检查辅助功能授权；测试中重新打包后必须重新检查，不能沿用旧包的授权结果。
2. 运行 `bash scripts/build-fixture.sh`，打开 `.build/Jumpo Window Fixture.app`。临时绑定一个空槽位，保留已有用户绑定。
3. 从其他应用进入测试应用；分别快速触发和间隔超过 1 秒触发，检查 A/B/C 都可到达。按钮测试与实体全局快捷键分别记录。
4. 在测试应用菜单选择“最小化所有测试窗口”（⌘M）；从自身日志确认全部最小化，再触发一次 Jumpo。先核对日志中一个窗口恢复、另外两个仍最小化，再查看测试界面，避免界面读取改变结果。
5. 关闭 Jumpo 的“恢复最小化窗口”，再次最小化所有测试窗口；触发后应保持最小化并报告应用级结果。完成后恢复原设置。
6. 用“恢复所有测试窗口”还原测试环境，点击“打开测试对话框”；触发 Jumpo 时应保留 Sheet 并提示先处理对话框。关闭 Sheet 后窗口循环应恢复。
7. 移除临时槽位绑定并退出测试应用；确认用户原有绑定和窗口策略未被改变。

## 0.3.0 修复：HUD 背景圆角与 Finder 无窗口（2026-10-05）

### 本次环境与构建

- 同一台 macOS 27.0.1（26A434）/ Apple Swift 6.4。
- `swift test --disable-xctest`：51 项通过（新增 3 项协调器、3 项窗口策略）。构建与打包沿用受控环境，SwiftPM 使用 `--disable-sandbox` 规避嵌套沙箱报错。
- 由于屏幕录制权限被拒，无法用系统截图核对；改用两类可复核证据：应用自身对窗口 PNG 的捕获，以及运行时图层树 dump。

### HUD 背景圆角

- 观察：`hudWindow` 材质在 macOS 26/27 上是一层不透明白色（运行时 dump 为 `rgb 0.96 alpha 1.0`），而 `blendingMode = .behindWindow` 的材质由窗口服务器合成，不遵循 CALayer 的 `cornerRadius`；因此圆形内容之外露出白色直角。应用自身截图会走图层遮罩，所以截图看起来是圆的，屏幕不是。
- 处理：给 `NSVisualEffectView` 设置效果级 `maskImage`（41×41，cap insets 20，`resizingMode = .stretch`），并保留图层圆角。内容与内容区样式未改动。
- 已验证：插桩实跑真实 HUD，mask 生效（`maskImage 41×41, capInsets 20`），面板逐像素与改前一致，未被蒙掉。
- 未验证：真实屏幕上的最终观感（需用户目视确认）。

### Finder 快捷键

- 观察：Finder 常驻运行且 `launchDate` 为 `nil`；窗口列表显示它的桌面窗口（layer -2147483603，铺满 1440×900）与普通文件夹窗口（layer 0）。捆绑副本实跑记录：跳 Chrome 与跳 Finder 都能前台化，Finder 文件夹窗口也会被抬到最前（`NSRunningApplication.activate` 足够）。
- 缺口：PRD 12.4 的两条规则未实现——① 桌面窗口未从枚举中排除；② 经权限确认无标准窗口时未打开主目录窗口。因此 Finder 没有窗口时，只做应用级激活，屏幕上没有任何可见变化。
- 处理：枚举时对 Finder 排除“铺满整块显示器且没有关闭按钮”的窗口（桌面窗口没有窗口控件）；`WindowSnapshot.windows` 为空且枚举可用时，通过 `NSWorkspace.open(主目录)` 取得可操作窗口，并新增 `JumpStatus.windowOpened`（“已打开 Finder 窗口”）。最小化窗口仍不重复创建窗口。
- 回归与修正（用户实测报回）：第一版只用“铺满显示器”判断，而用户把菜单栏与 Dock 设为自动隐藏，`visibleFrame == frame`，Chrome/ChatGPT/Dia 等最大化窗口同样铺满 1440×900，于是全部被当成桌面排除，同应用多窗口循环失效。现改为仅对 Finder 生效，并要求该窗口没有关闭按钮；`zoomedWindowFillingADisplayStaysSelectable` 固定该回归。
- 未验证：以上两条都需要辅助功能授权。当前构建仍未获授权（见 0.3.0 小节），因此**未在实机确认 Finder 无窗口路径**；AX 路径需授权后复测，且 ad hoc 重新签名后可能需重新授权。
