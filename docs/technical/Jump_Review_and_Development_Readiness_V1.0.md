# Jump / Jumpo — 文档评审与开发准备

> 日期：2026-09-30  
> 对应版本：三份 V1.0 文档的 R2 修订（2026-10-04 范围调整）  
> 状态：0.3.0 已加入 HUD 实现；实际验证状态见文末链接

2026-10-04 用户决定暂缓全局快速搜索，使用 macOS 聚焦搜索满足需求。下文原评审中的 Search 设计与阶段清单按此范围调整执行；下一阶段为 HUD，搜索不作为当前版本验收条件。

## 1. 评审结论

产品方向明确：为本地常用应用建立固定快捷键，同一个入口处理启动与切换；窗口恢复、循环和搜索在系统权限及目标应用支持范围内提供。原有三份文档覆盖较全，但版本范围、输入状态、窗口循环、失败判定与分发方案存在会影响实现的歧义。

本次直接修改现有文件，保留文件名和产品版本号，新增 R1 修订日期；原始文件完整保存在 [评审前归档](../archive/2026-09-30_before_review/)。目录名称为 Jumpo；[分享对话](https://chatgpt.com/share/6abce260-14c4-83e8-9dc2-7a40ed61e4e8) 中 Jumpo 仍是候选名称，因此未将原代号 Jump 全文替换为已确定品牌。

本次未扩大为通用启动器、自动化平台或 AI 产品。

## 2. 已修正的问题

| 问题 | 本次处理 | 主要位置 |
|---|---|---|
| Picker 在范围表为 P1，却出现在首版界面和验收中 | 保留未来设计，全部明确为 V1.1；首版不展示相关入口 | PRD 0、15、25；UI 0、8、24 |
| 超时重置和“当前 App 再按即循环”冲突 | 超时结束旧会话；当前 App 仍在前台时从当前窗口进入下一项 | PRD 6.5、11；技术 12、27 |
| 每次激活更新最近顺序，可能只能在两窗间往返 | 循环使用稳定快照，处理关窗、新窗和自动按键重复 | PRD 6.5；技术 12 |
| 长按 Option 可能干扰输入和其他快捷键 | 明确取消条件、完整修饰键匹配、监听降级和快捷键暂停 | PRD 10、13；UI 6；技术 9、10 |
| 空槽位隐藏后布局变化，未定义是否占用按键 | 固定 3 × 3 位置；空/禁用槽位不注册全局按键 | PRD 10；UI 5、6 |
| 菜单打开 HUD 时没有“松开 Modifier”动作 | 区分长按提示 HUD 和可交互菜单 HUD | PRD 13；UI 6；技术 15 |
| 槽位替换、重复 App、全局 Trigger 数据不一致 | 明确确认/撤销、移动/交换、统一修饰键和注册失败回滚 | PRD 9、10；UI 5、11 |
| 多窗口搜索顺序含糊，更新可能误选 | 匹配程度优先、同层状态排序、稳定目标身份、旧查询丢弃 | PRD 14；UI 7；技术 24 |
| 焦点恢复可能把用户拉回旧 App | 仅取消且焦点仍属于 Jump 时恢复；成功跳转不恢复旧焦点 | UI 6；技术 15 |
| 将未知窗口数量当成无窗口 | 增加 unknown 状态，区分隐藏、最小化、无窗口和枚举失败 | PRD 9、11、12；技术 7 |
| Bundle ID、标题、PID 被误用为稳定身份 | 内部 App ID；明确安装副本、进程会话和 AX 运行时身份 | PRD 9；技术 4、7、22、23 |
| AX 调用卡住或旧启动回调抢焦点 | 有界后台 AX 调用、请求失效检查、总超时与最多一次重试 | PRD 11；技术 5、11、26、27 |
| API 调用成功被视为到达成功 | 分别记录请求提交、应用成功、窗口成功、降级、失败和超时 | PRD 11、24；技术 6、11 |
| 沙盒方案过于乐观 | 完整版按非沙盒官网分发准备；MAS 不列为首版并行实现 | PRD 25；技术 20、35 |
| `99.9%` 和延迟数字缺少测量定义 | 删除无样本成功率承诺，区分冷/热、内部/端到端耗时，定义采样 | PRD 22、24、26 |
| 引导要求一次配置过多，启动项默认开启 | 至少配置 1 个即可开始；登录启动默认关闭，由用户主动开启 | PRD 17、18；UI 11、12 |
| 窗口历史、埋点和首版范围混在一起 | 窗口信息仅会话内存；V1.0 不接远程埋点，后续统计单独评审 | PRD 21、24；技术 25 |
| 隐藏菜单/Dock 后可能找不到设置 | 再次打开 App 必须恢复设置入口；关闭窗口与退出明确分开 | PRD 19；UI 9；技术 14 |

## 3. 技术依据与验证边界

- Apple 明确列出辅助工具使用 Accessibility API 与 App Sandbox 的限制，因此完整窗口功能的官网版本是当前实现方案。这是根据官方限制作出的项目方案选择，不是上架结论。[Apple App Sandbox 文档](https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox)
- 全局事件观察与快捷键注册需要分开：`NSEvent` 全局 monitor 不能阻止原事件传递，也不接收发给本应用的事件。已核对 Apple 文档入口与本机 `NSEvent.h`；权限和具体输入路径仍需实测。[NSEvent 文档](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:))
- 已核对本机 SDK 的 `RegisterEventHotKey`、`kEventHotKeyExclusive`、`AXUIElementSetMessagingTimeout` 和激活接口注释；这些是 API 声明证据，不是产品运行证据。SDK 路径可用 `xcrun --show-sdk-path` 重查。
- `.activateIgnoringOtherApps` 已弃用；按键后实际前台状态需要另外确认。[Apple ActivationOptions 文档](https://developer.apple.com/documentation/appkit/nsapplication/activationoptions)
- 窗口元数据存在权限限制，不应为补齐标题把屏幕录制权限加成产品前提；首版使用 AX 文本元数据，不做窗口截图。[Apple WWDC19 说明](https://developer.apple.com/videos/play/wwdc2019/701/)

文档评审阶段完成了全文阅读、交叉核对、官方资料/SDK 声明核对和 Markdown 结构检查。**这些评审本身未验证快捷键权限表现、实际窗口切换、跨 Space、资源占用、签名公证或应用兼容性。** 后续原型实测单独记录。

## 4. 开发顺序与阶段产出

| 阶段 | 内容 | 完成依据 |
|---|---|---|
| 1. 最小应用切换原型 | 原生菜单栏 App、绑定一个本地 App、注册快捷键、启动/激活、错误反馈 | 未运行/已运行/隐藏场景及无窗口权限路径有实际记录；不重复启动、不产生额外字符 |
| 2. 输入与窗口验证 | 长按状态机、取消规则、AX 窗口识别/恢复/循环、并发与超时 | 三窗循环、权限撤销、失效窗口、A 后 B 快速触发均按规则处理 |
| 3. 首版完整交互 | 1～9 槽位、My Shortcuts、Apps、HUD、设置与引导；全局搜索暂缓 | 按 PRD 第 26 节当前范围验收；按 UI 流程检查真实界面 |
| 4. 兼容与交付 | 多屏/Space/全屏、睡眠、长期运行、登录项、安装更新、签名公证 | 精确环境矩阵、通过/降级/失败/未测记录；具备可安装版本 |

技术文档第 33 节给出了五项 POC 的输入、验证重点和产出。已建立 Swift Package 工程；0.2.3 完成窗口恢复与循环的部分实机验证，0.3.0 加入长按提示和菜单 HUD，验证范围见原型记录。

## 5. 尚未确定的事项

这些事项未写成已经确认或已经验证的事实：

- 正式产品名是否采用 Jumpo；Bundle ID 的组织前缀。
- 最低 macOS 版本、Intel 是否纳入首版；以目标用户和可获得测试设备确定。
- Option 默认组合和 220ms 长按阈值的实际输入兼容性；先保留原设计，再用 POC 调整。
- 开发/发布签名条件。当前 `xcode-select -p` 指向 CommandLineTools；正式 App 构建前需确认完整 Xcode 与所用 SDK。
- 商业化方式、授权/付费、自动更新实现；不作为应用切换原型的前置条件，正式发布前单独确定。
